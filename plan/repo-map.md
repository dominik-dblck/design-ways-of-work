# The repository map · its notebook

One map of the way of working (W118): this repository, then its products, then what each one takes. Refined
point by point by `design-refine`'s checklist: one point at a time, its home first, two or three options on an
axis, the pick and why the others lost. The prototype that asked the questions stands in this session's
scratchpad: a script reading the repository into a typed module, and one page of six views; it is a drawing,
not the build.

## The points

1 · its home · decided 14 Nov: this repository's own tool, a script writing typed data from this repository
and the products' clones, and a page from the design system. The PM first picked a page template in
`design/app/pages`, then corrected it within the hour: the architecture holds both sides, and a build
repository never takes a design page. A page left in a scratchpad lost as well: it holds no rule.

2 · what it shows, in which order · decided 14 Nov, the PM's words: the way of working first, then the
products (each a design and a build repository), then what each one takes: its skills, its rules, its checks,
its ways of working.

3 · how it is drawn: the levels in 3D, by CSS or by WebGL, both drawn on one scene model so they compare on
the same data · open; the PM compares the two drawings.

4 · each shape it draws a `componentsSpec` row; a new one a draft · open.

5 · the build: one component a file, the data's writer a tool with its test · open.
