# Components

`app/components/` in atomic design: a tier is counted from what a component imports, never judged from its size. The tiers are counted by tests that run on `app/components/` already; the rows still held by `review` get their test with the first component.

| Rule                                                                                                                                                                                                                                                                        | Gate                                                                                                                                         | Exceptions                                    | Why                                                                                                                                                           |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A tier is what a component imports from `app/components/`: an atom nothing, a molecule atoms and at most one other molecule, an organism two or more molecules or a screen's own flow, a template a page's layout.                                                          | ESLint `boundaries/dependencies` (an atom, a molecule above its tier) · ESLint `wow/molecules-compose-one-molecule` · `review` (an organism) | —                                             | Counted, not judged, so two people sort a component the same way.                                                                                             |
| An organism is reached through its barrel, its `index.ts`: a page mounts one, and another organism renders it, only through that file.                                                                                                                                      | ESLint `boundaries/dependencies` (past a barrel)                                                                                             | —                                             | The barrel is the organism's face; the files behind it can move.                                                                                              |
| A renderer is an app inside the app: it draws another product's design system, with tiers and colours of its own. It imports nothing of the app around it, and the app enters it at a component's barrel, its `index.ts`, whatever that component's tier there.             | ESLint `wow/renderer-stands-alone` · ESLint `boundaries/dependencies` (its tiers, held within it)                                            | —                                             | The app sees a renderer from outside, one embedded whole, as it sees a package's component; the dependency runs one way, the app to the renderer, never back. |
| A molecule reads no context, and an organism reads one in its `providers/` or `hooks/` alone: `useContext` and `use` are imported by name there, and a hook is never read off `React`.                                                                                      | ESLint `boundaries/dependencies` (a context) · ESLint `no-restricted-syntax` (a hook off `React`)                                            | —                                             | A component that reads a context draws what it fetched, not what it was handed; a read kept in one layer is found in one place.                               |
| Every component has the organism's folder shape: the root holds `{Name}.tsx` and `index.ts`, every other file sits in `components/`, `hooks/`, `utils/`, `types/`, `constants/`, `providers/`, `services/` or `__tests__/`, its name carrying the component's (`names.md`). | `lint:files` (ls-lint, a component's folder) · ESLint `wow/file-names-its-purpose` (a part's name)                                           | an atom has no `components/`, having no parts | One shape everywhere, so a file is found without a search.                                                                                                    |
| A component file holds one component and its props type; a second component goes to `components/`, a type to `types/`, a helper to `utils/`, a constant to `constants/`, a hook to `hooks/`.                                                                                | ESLint `wow/component-file-holds-its-component`                                                                                              | a provider's file, an icon's                  | A file opened for a component shows that component and nothing else.                                                                                          |
| Hover text is a tooltip (the build side's `Hint`); no element carries a native `title`.                                                                                                                                                                                     | ESLint `wow/markup-syntax` (a hover text)                                                                                                    | —                                             | One look and one delay for every hover.                                                                                                                       |
| Every component is a row of `app/styles/components.spec.ts` (built into `fixtures/data/components.spec.json`).                                                                                                                                                              | `review`                                                                                                                                     | —                                             | A shape the wireframes do not draw is a question, not a component.                                                                                            |
| Every glyph is Lucide's, through `lucide-react` by name, never a copied SVG (D10).                                                                                                                                                                                          | `review`                                                                                                                                     | —                                             | One set, one stroke, sizes from the tokens.                                                                                                                   |
| A page reads the sheet's entries as modules and holds no rule of the sheet; it draws the answer.                                                                                                                                                                            | `review`                                                                                                                                     | —                                             | A rule copied onto a page is decided twice, and the copies drift.                                                                                             |
