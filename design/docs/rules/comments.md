# Comments

The default is none. The code and the
file's header say what; `git log`, the notebooks and `docs/process/decisions.ts` say when, who and why it was decided.

| Rule                                                                                                                                                      | Gate                                                                                                      | Exceptions                                               | Why                                                                                                            |
| --------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| The file's header (`responsibility.md`) is the one comment that says what a file does.                                                                    | `aFileStatesItsJob`                                                                                       | —                                                        | Said once at the top, it is not said again above every function.                                               |
| A JSDoc past the header is one line, directly above an export, stating a contract its name and type do not show. It never restates the name or the type.  | `commentsAreInvariants`                                                                                   | tests · generated files                                  | It shows on hover wherever the export is used; a restated name is noise the hover repeats.                     |
| A `//` comment is one line about the code under it, saying what breaks if it is undone.                                                                   | `commentsAreInvariants`                                                                                   | tests · generated files                                  | It is the one question nothing else in the project answers.                                                    |
| A file carries at most 10 comment lines outside its header.                                                                                               | `commentsAreInvariants`                                                                                   | tests · generated files                                  | Past ten, a file is being explained rather than written.                                                       |
| No date, ticket, epic, review, stage or chronicle in a comment.                                                                                           | `commentsAreInvariants`                                                                                   | a part named for the epic it holds names that epic (D13) | Narration reads as authoritative and goes stale the first time somebody edits without adding to it.            |
| A rule or a checklist line carries no history either: no date, ticket, criterion, attribution, stage, epic or finding code in its words or its why (D27). | `aRuleCarriesNoHistory`                                                                                   | —                                                        | A rule read with its incident is read as being about that incident; the history stays in `legacy/` and in git. |
| A file still written in the old style is cleaned when it is edited: delete rather than preserve, shorten what is worth keeping.                           | `review`                                                                                                  | —                                                        | Each edit shrinks the debt instead of carrying it forward.                                                     |
| An ESLint directive is one line naming its rule, its reason after `--`; it is not counted in the ten.                                                     | ESLint `@eslint-community/eslint-comments/require-description` · `reportUnusedDisableDirectives: "error"` | —                                                        | An exception is read where it is made, and one whose rule no longer fires goes.                                |
