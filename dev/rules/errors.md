# Errors

A refusal is an answer, not an exception: it travels as a value and the caller branches on it.

| Rule                                                                                                                                                                                                                                                                           | Gate                                                                            | Exceptions | Why                                                                           |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- | ---------- | ----------------------------------------------------------------------------- |
| Every answer is `{ ok: true, … }` or `{ ok: false, kind, … }`, `kind` one of `REFUSAL_KINDS`, each with one status at the edge (`rule` 409, `unauthenticated` 401, `cross-site` and `forbidden` 403, `missing` 404, `malformed` 400, `error` 500).                             | `tsc` (`satisfies Record<RefusalKind, number>`) · `everyDocumentEndpoint`       | —          | The caller branches on a closed set and a status nobody has to look up.       |
| A domain refusal carries its rule key, one sentence for a person, what it fired on, the current stream version, and what would make the call pass (`fix`, `null` when nothing recovers); the sentence is read from `packages/domain/refusals/refusalCatalog.ts`, never copied. | `refusals.test` · `theWordsFollowTheGlossary`                                   | —          | The person reads why, and the caller knows what to send next.                 |
| The browser calls the server through `app/utils/requestUtils.ts` alone; it never throws for an HTTP answer, and a refusal comes back as a value.                                                                                                                               | `oneFetch` (one caller) · `review` (never throws)                               | —          | One door, so a lost answer and a refusal are handled the same way everywhere. |
| An unexpected throw at the edge answers 500 `{ ok: false, kind: 'error', id }`: the detail is logged on the server under the `id`, nothing internal goes on the wire, and no session is renewed.                                                                               | `theSessionLifetime` (renews nothing) · `review` (nothing internal on the wire) | —          | A stack trace on the wire is a map of the server.                             |
| A render that throws reads one line and Retry: `app/error.tsx` inside the app's theme, `app/global-error.tsx` in a document of its own when the layout itself threw.                                                                                                           | `theErrorBoundaries`                                                            | —          | Retry asks the segment again instead of redrawing what failed.                |
| A read that fails shows its line and a Retry that asks again; the screen never goes blank.                                                                                                                                                                                     | `everyPathIsWalked` (the lost answer)                                           | —          | A blank screen tells nobody what happened or what to do.                      |
| A promise is awaited, returned, or handed to `void` where nothing waits on it; none floats.                                                                                                                                                                                    | ESLint `no-floating-promises`                                                   | —          | A floating promise's rejection reaches no boundary and no log.                |
