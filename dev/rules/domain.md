# Domain

`packages/domain` holds the rules, the log and the replay; everything else hands it what it needs
and reads what it answers. The principles are `CLAUDE.md` → How the work goes; these rows are the
boundaries the scans hold.

| Rule                                                                                                                                                                                              | Gate                                                                                                   | Exceptions | Why                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ---------- | -------------------------------------------------------------------------------------------- |
| `packages/domain` imports no framework, no driver, no built-in and nothing outside itself that its `allowed` list does not name; it reaches for no request, session, header, environment or `pg`. | `domainBoundary` · `theDomainNamesNoDatabase`                                                          | —          | The rules run anywhere and are proved without a server.                                      |
| The store and the directory reach the domain as arguments: each is opened or built once, at the edge.                                                                                             | `storeHandedIn` · `directoryHandedIn`                                                                  | —          | The rules name a port, never a database.                                                     |
| The store port is twelve operations and imports nothing from the model or the log.                                                                                                                | `adapterIsOpaque`                                                                                      | —          | An implementation knows rows, not rules.                                                     |
| The log is appended through one door, `runCommand`, and by the seed; there is no third caller.                                                                                                    | `oneDoor`                                                                                              | —          | Every change is an event that passed the rules.                                              |
| A stream belongs to one document.                                                                                                                                                                 | `oneLogOneDocument`                                                                                    | —          | A document's history is read in one place.                                                   |
| A refusal is one of three `ok: false` shapes, and nothing builds a fourth.                                                                                                                        | `theThreeShapes`                                                                                       | —          | Every caller branches on a closed set.                                                       |
| A command arrives as a decide, never declared under a name of its own; a derived event is built only by the decide that produces it, and no command lists one in its emits.                       | `noCommandsYet` · `aDerivedEventHasNoCommand`                                                          | —          | An event is produced in one place, so its meaning cannot split.                              |
| Nothing reads `owner` off a block, a spec or a catalog.                                                                                                                                           | `nothingReadsAnOwner`                                                                                  | —          | Who may act is the rules' answer, not a field on the data.                                   |
| The approving role is Product; no file names a CEO.                                                                                                                                               | `theApprovalIsProduct`                                                                                 | —          | A renamed word is gone everywhere, or it comes back.                                         |
| The log is called tamper-evident and nothing stronger: the chain shows that nothing changed after it was written.                                                                                 | `nothingClaimsTamperProof`                                                                             | —          | Append-only in code is not protected storage, and a promise the system cannot keep misleads. |
| The specification is read where it sits, in the design project; a spec file a test needs is a fixture copied byte for byte with its hash, and there is no `spec/` folder.                         | `noSpecFolder` · `everyFixtureRootIsHeld` · `theSpecHoldsTogether` · `theComponentSpecIsTheDesignSide` | —          | A second copy of the spec is the one that drifts.                                            |
