# Tests

A test sits where its project reads it, proves something that can fail, and never touches a
database it does not own. `packages/domain` adds `.claude/patterns/domain-testing.md`, which wins
where the two differ; browser flows follow `.claude/skills/e2e/_shared.md`.

| Rule                                                                                                                                                                                                                                                                                                                                                                                  | Gate                                               | Exceptions                                                                                          | Why                                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| A test imports the real function and asserts exact values; it never copies the logic, never mocks the module under test, and is seen red once with its condition broken.                                                                                                                                                                                                              | `noTestMocksItsSubject` · `review`                 | —                                                                                                   | A test that cannot fail proves nothing.                                                                                     |
| A scan proves itself on a synthetic `{ path, text }`, never on a file planted in the tree.                                                                                                                                                                                                                                                                                            | `aScanPlantsNothing`                               | `baseline.ts`, which writes the lists under `BASELINES=write`                                       | Suites walk the tree in parallel, and a planted file is read by every one of them.                                          |
| A scan that lands on code already breaking it starts from its list, `tests/architecture/baselines/{scan}.json`, started once by `BASELINES=start:{scan}`, refused when it exists; the list only shrinks: a new offender is red, and so is a fixed one still listed, until `BASELINES=write` drops it, and a list it empties is removed: a scan with no list holds every offender red. | `baseline.test`                                    | —                                                                                                   | A gate that waits for the code to be clean never lands; one that lets the list grow, or refill once clean, holds nothing.   |
| A skipped test names what it waits on.                                                                                                                                                                                                                                                                                                                                                | `theSeventhTier` (the `postgres` tiers) · `review` | —                                                                                                   | A skip without its reason becomes permanent.                                                                                |
| Production reads no test switch.                                                                                                                                                                                                                                                                                                                                                      | `noTestOnlyBranchInProduction`                     | —                                                                                                   | A branch only a test takes ships untested in the other direction.                                                           |
| A drawn element is asserted present one way, `expect(getBy…(…)).toBeTruthy()`.                                                                                                                                                                                                                                                                                                        | `aPresenceIsReadOneWay`                            | a `queryBy…` asserted with a message, which names what is missing instead of throwing               | A `getBy` already throws when nothing is drawn; `toBeDefined` and `not.toBeNull` beside it are one fact in three spellings. |
| Time is moved with fake timers (`vi.useFakeTimers`, `page.clock`), never waited out.                                                                                                                                                                                                                                                                                                  | `timeIsMovedNotWaited`                             | a race against a real database (`deleteAssetRoute`'s `aWhile`, the store contract's `holding`)      | A wait is slow and still flaky; a moved clock is neither.                                                                   |
| A test's path decides its project, as the table below and `vitest.config.mts` give them; nothing in the test, no tag or flag, moves it.                                                                                                                                                                                                                                               | `threeTiers` · `statedCounts`                      | —                                                                                                   | The place of a file is its tier, so a test cannot quietly run somewhere else.                                               |
| A tier that needs a switch in both positions is two projects over one include list, differing by one environment variable (`STORE_IMPL`, `AUTH_GOOGLE_ID`); a test never sets one in a `beforeAll`.                                                                                                                                                                                   | `storeSuiteRunsBoth` · `review`                    | —                                                                                                   | An environment is process-global: one set in a file leaked into the file beside it.                                         |
| The domain suite runs with no database at all.                                                                                                                                                                                                                                                                                                                                        | `threeTiers`                                       | —                                                                                                   | The rules are proved without the store that keeps them.                                                                     |
| A database belongs to the project that can destroy it: a project that isolates by the `test-` prefix shares `content_test`, a project that empties or drops one owns its own; no test names `DATABASE_URL`.                                                                                                                                                                           | `theAdminLoginStaysOut`                            | —                                                                                                   | Safety never rests on run order, and a `yarn test` beside a `yarn dev` once emptied the developer's database.               |
| `content_test` is reset once per run, by `tests/setup/resetDatabase.ts`, and every id a test writes there begins `test-`.                                                                                                                                                                                                                                                             | `oneReset` · `review` (the prefix)                 | —                                                                                                   | Isolation is in the model, not in a cleanup that a shuffle can run at the wrong moment.                                     |
| `tests/helpers/` holds a helper two tiers import; a helper one tier imports lives in the `__tests__/` of the nearest folder holding its users; no project's `include` matches it, and no tier's fixture lives there.                                                                                                                                                                  | `aHelperServesTwoTiers` · `review`                 | `tablesInTheTestDatabase`, since `theEdgeIsTheOnlyDoor` keeps `pg` out of `app/api`, tests included | A helper's place is decided by what imports it, not by who wrote it first.                                                  |
| Every public function and component has its main path and its edges tested: empty, `null`, a boundary, each error state.                                                                                                                                                                                                                                                              | `review` · `yarn test:coverage`                    | —                                                                                                   | The edges are where a change breaks what nobody looked at.                                                                  |
| In a `*.test-d.ts`: every `@ts-expect-error` fails without itself; `toEqualTypeOf`, not `toExtend` (the deprecated `toMatchTypeOf`), where two brands share a primitive; no cast.                                                                                                                                                                                                     | `brandsCrossOnce` (no cast) · `review`             | —                                                                                                   | `expectTypeOf` is a no-op at run time, so only `tsc` makes the assertion real, and twin brands pass a loose one.            |
| Coverage never drops: pre-push runs `yarn test:coverage` against floors in `vitest.config.mts`, the whole and per area (domain, api and services, organisms), which `autoUpdate` raises to the whole percent a run reaches; a file leaves the count only through `tests/architecture/coverageWaivers.json`, naming the e2e flow that walks it.                                        | `yarn test:coverage` · `aCoverageWaiverIsWalked`   | the four files the waiver list names                                                                | A split that loses a test loses a point, and the push says which area before anyone has to notice.                          |

## The projects

| What you are testing                      | Project                                 | Where the file goes                                    | Database                                  |
| ----------------------------------------- | --------------------------------------- | ------------------------------------------------------ | ----------------------------------------- |
| the domain — replay, commands, refusals   | `domain`                                | `packages/domain/**/*.test.ts`                         | never                                     |
| a store implementation, against the port  | `store-contract:memory` and `:postgres` | `tests/store-contract/**/*.test.ts`                    | one suite, run twice · `content_contract` |
| what only a real database can answer      | `postgres`                              | `tests/postgres/**/*.test.ts`                          | real, or skipped                          |
| the seed, against a store it is handed    | `seed`                                  | `tests/seed/**/*.test.ts`                              | no · memory                               |
| an API route over HTTP                    | `endpoint`                              | `app/api/**/*.test.ts`                                 | real · `content_test`                     |
| an API route with Google sign-in off      | `endpoint:persona`                      | `app/api/**/__tests__/**/*.switchOff.test.ts`          | real · `content_test`                     |
| a document route, after the endpoint tier | `endpoint:documents`                    | `app/api/{documents,assets}/**/__tests__/**/*.test.ts` | real · `content_test`                     |
| the two database commands                 | `scripts`                               | `tests/scripts/**/*.test.ts`                           | real · `content_scripts`                  |
| the seed, read back over HTTP             | `seeded`                                | `tests/seeded/**/*.test.ts`                            | real · `content_test`                     |
| a component, a hook, a service            | `app`                                   | beside it, or `__tests__/`                             | no                                        |
| a boundary in the configuration           | `architecture`                          | `tests/architecture/**/*.test.ts`                      | no                                        |
| a type · what only the compiler can say   | `types`                                 | `tests/types/**/*.test-d.ts`                           | no                                        |

13 vitest projects, one file. `yarn test` runs all 13; `yarn test --project domain` runs the domain
alone.

## The databases

One Postgres from `docker compose up -d`, four databases from `db/init/001_databases.sql`:

| Database           | Variables                             | Who opens it                                                    |
| ------------------ | ------------------------------------- | --------------------------------------------------------------- |
| `content_dev`      | `DATABASE_URL` · `DATABASE_ADMIN_URL` | `yarn dev`, and `yarn db:seed` / `yarn db:reset` run by hand    |
| `content_test`     | `DATABASE_TEST_*`                     | `postgres`, `endpoint`, `seeded`, `architecture` · prefixed ids |
| `content_scripts`  | `DATABASE_SCRIPTS_*`                  | `scripts`, whose tests run `DROP SCHEMA`                        |
| `content_contract` | `DATABASE_CONTRACT_*`                 | `store-contract:postgres`, whose `open()` TRUNCATEs every table |

Each project maps its own pair to the names `openStoreService` expects, in `vitest.config.mts`, the
one file where the four meet. The init SQL runs on an empty data directory only; a machine on the
earlier single-database compose removes its volume once:

```
docker compose down -v && docker compose up -d
yarn db:migrate
yarn db:migrate --for test
yarn db:migrate --for scripts
yarn db:migrate --for contract
```
