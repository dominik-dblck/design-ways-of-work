# Comments

The default is none. The code and the file's header say what; `git log` and the work trail say when,
who and why it was asked for.

| Rule                                                                                                                                                                                                              | Gate                                                                                                      | Exceptions                                                         | Why                                                                                                 |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| The file's header (`responsibility.md`) is the one comment that says what a file does.                                                                                                                            | `aFileStatesItsJob`                                                                                       | —                                                                  | Said once at the top, it is not said again above every function.                                    |
| A JSDoc past the header is one line, directly above an export, stating a contract its name and type do not show: what `null` means, a unit, what the server checks again. It never restates the name or the type. | `commentsAreInvariants` (one line, above an export) · `review` (a contract, not a restatement)            | tests · generated files · the files on its list, which only shrink | It shows on hover wherever the export is used; a restated name is noise the hover repeats.          |
| A `//` comment is one line about the code under it, saying what breaks if it is undone.                                                                                                                           | `commentsAreInvariants`                                                                                   | tests · generated files · the files on its list, which only shrink | It is the one question nothing else in the repository answers.                                      |
| A file carries at most 10 comment lines outside its header.                                                                                                                                                       | `commentsAreInvariants`                                                                                   | tests · generated files · the files on its list, which only shrink | Past ten, a file is being explained rather than written.                                            |
| No date, ticket, review, stage or chronicle in a comment.                                                                                                                                                         | `commentsAreInvariants` · `theCodeNamesNoTicket`                                                          | —                                                                  | Narration reads as authoritative and goes stale the first time somebody edits without adding to it. |
| A file still written in the old style is cleaned when it is edited: delete rather than preserve, shorten what is worth keeping.                                                                                   | `review`                                                                                                  | —                                                                  | Each edit shrinks the debt instead of carrying it forward.                                          |
| An ESLint directive is one line naming its rule, its reason after `--` (`// eslint-disable-next-line id-length -- colour channels`); it is not counted in the ten.                                                | ESLint `@eslint-community/eslint-comments/require-description` · `reportUnusedDisableDirectives: "error"` | —                                                                  | An exception is read where it is made, and one whose rule no longer fires goes.                     |
