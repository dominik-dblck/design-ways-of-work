# Scripts

`scripts/` holds the commands a person runs by hand, each behind a `yarn` script; their tests are
`tests/scripts/`.

| Rule                                                                                                                                                                                                                                                                                                           | Gate                                                                     | Exceptions | Why                                                                                                                                                            |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `yarn db:migrate` takes a target (`--for test`, `--for scripts`, `--for contract`, none for `content_dev`) and never a `DATABASE_URL` the caller exported.                                                                                                                                                     | `theAdminLoginStaysOut` · `review`                                       | —          | CI migrates three databases without ever setting the developer's.                                                                                              |
| `yarn db:seed` and `yarn db:reset` refuse `NODE_ENV=production` at their first line, before a connection opens; the seed refuses a database that holds anything.                                                                                                                                               | `theTwoCommands`                                                         | —          | Neither mistake can be undone, so the guard is doubled on purpose.                                                                                             |
| A script imported does nothing: its top level declares, and what it does, its loader hooks and `process.loadEnvFile()` included, sits in its `isRunDirectly(import.meta)` block.                                                                                                                               | `aScriptImportedDoesNothing`                                             | —          | A test that imported one at module scope would read `.env` and land on `content_dev`.                                                                          |
| A script runs under plain node, `NODE_FLAGS` before it: every `package.json` command that runs a `.ts`, and every node a file starts (`nodeArgsOf`); `package.json` holds no tsx and no `"type"`; a script is `.ts`, never `.mjs`, `.cjs` or `.js`.                                                            | `aScriptRunsUnderPlainNode`                                              | —          | A typeless `.ts` is ESM by its syntax and node says so on every run; tsx would compile it to CommonJS, and a `"type"` would move every file of the repository. |
| Nothing under `app/` imports `scripts/` or the seed.                                                                                                                                                                                                                                                           | `nothingShipsTheSeed`                                                    | —          | A command for a person never ships in the build.                                                                                                               |
| A generated file is written by its script and checked against a fresh run: `yarn skills` (the ticket skills), `generateTokens.ts` (the tokens), `renderComponentsDoc.ts` (`docs/components.md`).                                                                                                               | `skillsAreGenerated` · `tokensAreGenerated` · `renderComponentsDoc.test` | —          | A hand edit to a generated file is a red test, not a quiet disagreement.                                                                                       |
| `yarn snapshot` writes `.snapshots/snapshot-{ticket}.md`, gitignored: new files whole, changed ones as a diff against `feature/deblock-content`, opening with its contents and a reading order; docs, skills and the knowledge base are listed by name and left out.                                           | `ticketSnapshot.test`                                                    | —          | The design side cannot read this repository, so the work travels as text it can jump through.                                                                  |
| `yarn sheet:cache` reads a file of the design repository at a named commit, by `git cat-file`, into `.sheet-cache/` with its commit, blob id and digest, and every later reader takes the disk copy.                                                                                                           | `cacheSheet.test`                                                        | —          | One read of the sheet, so two readers cannot see two versions.                                                                                                 |
| `yarn sheet:take` reads a release by `git cat-file` at its full sha and holds every file it copies by a digest its one record names, its own or its module's; one file off, unnamed or missing refuses the take whole, and nothing is written.                                                                 | `takeRelease.test`                                                       | —          | A copy held against itself passes whatever was copied; the records are the other side's word for each byte.                                                    |
| `yarn e2e:pick` prints the e2e a change asks for, read off the import graph: none for a file no page, route, config, e2e helper or database reset loads; a suite for a file only its folder loads; every suite for the rest, a file the graph cannot read included.                                            | `e2eForChange.test`                                                      | —          | A chunk that moved tests or docs alone waits ten minutes for nothing, and a guessed family misses the suites that reach a screen through another.              |
| `yarn test:coverage` runs the suite with coverage through `coverageRun.ts`: a whole green run appends one row to `roadmaps/coverage/history.jsonl` (the sha, the tests, the four totals, the three parts the thresholds hold apart); a run with arguments writes no row and leaves the thresholds as they are. | `coverageRows.test` · `coverageChart.test` · `oneCommand`                | —          | A trend read off a habit has gaps, and a part's numbers in the history, or in the floors, would read as the whole.                                             |

## The commands

| Script                   | Command                                                            | What it does                                                                                                         |
| ------------------------ | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| —                        | `yarn db:up`                                                       | `docker compose up -d` · one container, the four databases made by `db/init/`                                        |
| `migrate.ts`             | `yarn db:migrate [--for test\|scripts\|contract]`                  | applies every migration as the owner                                                                                 |
| `dbSeed.ts`              | `yarn db:seed`                                                     | the seed's events, documents and groups through the ordinary append path                                             |
| `dbReset.ts`             | `yarn db:reset`                                                    | `DROP SCHEMA` + `CREATE SCHEMA` as the owner, the migration, then the seed                                           |
| `generateSkills.ts`      | `yarn skills [--out dir]`                                          | cuts `.claude/__fixtures__/ticket-pipeline.md` into the ticket skills and templates                                  |
| `takeRelease.ts`         | `yarn sheet:take --commit <sha> --record <path>[=<sha256>]`        | a release's modules, with what they import, into `packages/domain/sheet/__fixtures__/`                               |
| `cacheSheet.ts`          | `yarn sheet:cache <file> --commit <sha> [--repo path]`             | caches a file of the design repository at a named commit, with its blob id and digest                                |
| `ticketSnapshot.ts`      | `yarn snapshot [ticket] [--out path]`                              | collects what one ticket changed into one file                                                                       |
| `e2eForChange.ts`        | `yarn e2e:pick [--since ref]`                                      | the e2e suites the working tree's changes reach, or those since a commit                                             |
| `coverageRun.ts`         | `yarn test:coverage [vitest args]`                                 | the suite with coverage · a whole green run appends its row to `roadmaps/coverage/history.jsonl`                     |
| `coverageTrend.ts`       | `yarn coverage:trend [--last n]`                                   | the last runs as a table · every run drawn in `reports/coverage/trend.html`                                          |
| `verifyFixtures.ts`      | `yarn fixtures [--list]`                                           | checks every copied fixture against the digest the design side took · `--list` prints what is on disk                |
| `renderCurlDoc.ts`       | `yarn curl:doc`                                                    | runs the folder calls against the database and writes `docs/e00-curl.md`                                             |
| `readTicket.ts`          | `yarn ticket:read <ticket> [--print] [<a part of tickets.ts>]`     | a ticket's pack and its contract diff · `--print` the criteria · a fetched part of `tickets.ts` windows a stale pack |
| `checkReports.ts`        | `yarn reports:check <re-ports.json>`                               | each re-port row against the cached sheet: ready, applied or broken                                                  |
| `renderComponentsDoc.ts` | `node scripts/renderComponentsDoc.ts [--print]`                    | `docs/components.md` from `app/styles/components.spec.json` · `--print` writes nothing                               |
| `generateSeedFixture.ts` | `node scripts/generateSeedFixture.ts [--fixtures dir] [--out dir]` | the seed and the domain's emitted files from the copied sheet                                                        |
| `generateRunFixture.ts`  | `node scripts/generateRunFixture.ts [--fixtures dir] [--out dir]`  | `run.ts` from the copied `sampleRun.js` and `events.js`                                                             |
| `generateTokens.ts`      | `node scripts/generateTokens.ts [--check]`                         | `app/styles/tokens.ts` from the two CSS fixtures · `--check` compares and writes nothing                             |
